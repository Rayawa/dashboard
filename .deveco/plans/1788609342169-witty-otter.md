## Goal

将 app 的全新安装默认值改为：
- **振动强度** 默认 = `1`（灵动，原来 `0`=关闭）
- **材质等级** 默认 = `1`（轻柔，原来 `2`=流畅）

只改这两项默认值，不改动其它设置项（用户名、智感握姿开关、按钮位置等）、不改动任何 UI 文案与振动/材质交互逻辑。

## Scope / Non-goals

**In scope**
- `DEFAULT_VIBRATION_LEVEL` 与 `DEFAULT_IMMERSIVE_MATERIAL_LEVEL` 两个常量的取值。
- `getVibrationLevel()` 中「全新安装」分支的默认值回退。
- 为保持与代码内既有约定「`@StorageLink` 装饰器初始值必须与 `DEFAULT_SETTINGS` 一致」同步，更新两处设置相关的 `@StorageLink` 初始值。

**Non-goals**
- 不强制重置已有用户已保存的设置（已有用户保留自己的选择）。
- 不改动 `holdCheck`、`buttonPosition`、用户名等其它设置。
- 不改动 `tutorial.ets`、`appLog.ets` 中的说明文案与更新日志。
- 不改动 `hdsMaterial.MaterialType`（材质类型，仍是 `IMMERSIVE`），只改材质「等级」（level）。

## Current State And Constraints

- 默认值唯一定义在 [entry/src/main/ets/common/constants.ets](entry/src/main/ets/common/constants.ets)：
  - 第 35 行 `DEFAULT_VIBRATION_LEVEL = 0`（注释：`0 = 关闭，1 = 灵动，2 = 硬朗；全新安装默认关闭振动`）
  - 第 39 行 `DEFAULT_IMMERSIVE_MATERIAL_LEVEL = 2`（注释：`hdsMaterial.MaterialLevel.SMOOTH`）
- 材质等级枚举映射（由 settings.ets 标签与常量注释确认）：
  - `hdsMaterial.MaterialLevel.EXQUISITE` = 0 = 精美
  - `hdsMaterial.MaterialLevel.GENTLE` = 1 = 轻柔
  - `hdsMaterial.MaterialLevel.SMOOTH` = 2 = 流畅
- 持久化默认值组装在 [entry/src/main/ets/common/storage.ets](entry/src/main/ets/common/storage.ets) 的 `DEFAULT_SETTINGS`，其第 50 行注释明确要求 `@StorageLink` 装饰器初始值与此保持一致。
- `getVibrationLevel()` 存在「全新安装」专用分支：当 `vibrationLevel` 尚未写入磁盘时，读取旧版布尔开关 `vibrationON`，用 `legacyEnabled ? 2 : 0` 硬编码为 `0`（关闭），**绕过了** `DEFAULT_VIBRATION_LEVEL`，因此仅改常量无法让新装振动默认值生效，必须同步修正该分支。
- 材质等级无历史迁移逻辑，`getImmersiveMaterialLevel()` 直接读取 `DEFAULT_SETTINGS.immersiveMaterialLevel` 作为默认，故改常量即可生效。
- 启动时序：[entry/src/main/ets/ability/entry.ets](entry/src/main/ets/ability/entry.ets) 的 `onWindowStageCreate` 先 `await` `loadPersistedState()` 完成水合，再 `loadCurrentPage`。因此页面渲染前 AppStorage 已含真实值，`@StorageLink` 初始值实际是「死值」，仅用于保持代码约定一致，无功能副作用。
- ArkTS 约束：本改动不引入 `any`/`as` 断言之外的任何新增风险；`DiskStorage.has()` 返回 `Promise<boolean>`，可直接 `await`。

## Design

采用「常量 + 新装回退逻辑 + `@StorageLink` 初始值同步」三步，是最小且自洽的实现：

1. **改默认常量**（核心功能）：`DEFAULT_VIBRATION_LEVEL` 由 `0` → `1`，`DEFAULT_IMMERSIVE_MATERIAL_LEVEL` 由 `2` → `1`，并同步更新两行注释。

2. **修正 `getVibrationLevel()` 新装分支**（核心功能）：区分「有旧版 `vibrationON` 键的存量用户」与「全新安装」。存量用户沿用旧迁移（`true`→`2` 硬朗，`false`→`0` 关闭）；全新安装（磁盘无 `vibrationON` 键）回退到 `DEFAULT_SETTINGS.vibrationLevel`（即新的 `1` 灵动）。改动后的代码：

   ```ts
   // 兼容旧版布尔开关：已有用户沿用旧选择；全新安装没有旧值时使用新的默认值（灵动）。
   const hasLegacySwitch = await s.has(LEGACY_KEY_VIBRATION_ENABLED);
   const legacyEnabled = (await s.get(LEGACY_KEY_VIBRATION_ENABLED, false)) as boolean;
   const migratedLevel = hasLegacySwitch ? (legacyEnabled ? 2 : 0) : DEFAULT_SETTINGS.vibrationLevel;
   await s.set(KEY_VIBRATION_LEVEL, migratedLevel);
   return migratedLevel;
   ```

3. **同步 `@StorageLink` 初始值**（一致性，非功能必需）：把所有 `@StorageLink('vibrationLevel') ... = 0` 改为 `= 1`；把所有 `@StorageLink('immersiveMaterialLevel') ... = hdsMaterial.MaterialLevel.SMOOTH` 改为 `... = hdsMaterial.MaterialLevel.GENTLE`，把 `number` 型 `= 2` 改为 `= 1`。

## Risks And Compatibility

- **枚举名依赖**：`hdsMaterial.MaterialLevel.GENTLE` 的成员名来自 HarmonyOS UI Design Kit；若 SDK 版本成员名不同，`arkts_check`/编译会立即报错，届时按 SDK 实际成员名替换（取值仍为 `1`）。
- **存量用户影响**：对已写入磁盘 `vibrationLevel` / `immersiveMaterialLevel` 的用户无影响（`has(KEY_VIBRATION_LEVEL)` 为真即返回原值）；只有全新安装或从未设置过的旧版用户会得到新默认。
- **迁移边界**：旧版用户若存在 `vibrationON=false`，仍迁移为 `0`（关闭），符合「沿用旧选择」的既有语义；只有磁盘完全无 `vibrationON` 键时才会落到新默认 `1`。
- **SDK/兼容**：仅改常量与初始值，不涉及 API 变更、无新增权限、无 `module.json5` 改动。

## Rollback

- 代码：将 `DEFAULT_VIBRATION_LEVEL` 改回 `0`、`DEFAULT_IMMERSIVE_MATERIAL_LEVEL` 改回 `2`，恢复 `getVibrationLevel()` 原分支（`legacyEnabled ? 2 : 0`），并把所有 `@StorageLink` 初始值改回 `0` / `hdsMaterial.MaterialLevel.SMOOTH`（`number` 型 `= 2`）。
- 配置：本改动不涉及 `module.json5` 或资源文件，无额外配置回滚。
- 数据：默认值只作用于新装；如需让已拿到新默认值的测试设备回到旧默认，可清除 `app_storage`（或 `resetAllSettings` 前先恢复代码）。
