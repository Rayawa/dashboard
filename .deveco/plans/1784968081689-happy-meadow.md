## Goal

为除 `htmlPage` 以外的所有 WebView 页面注入 UA（User Agent），使其与主页面 `Dashboard.ets` 保持一致的 UA 行为。

## Scope / Non-goals

- **Scope**: 5 个使用远程 URL 的 WebView 页面
- **Non-goals**: `htmlPage.ets`（加载本地 `$rawfile` 的隐私政策页，不需要 UA）；Dashboard.ets（已有 UA 注入）

## Current State And Constraints

- 主页面 `Dashboard.ets` 已有的 UA 注入模式（参考基准）：
  - **全局 UA**：在 `aboutToAppear()` 中调用 `webview.WebviewController.setAppCustomUserAgent(customUserAgent)`，它是静态类级 API，对进程内所有 WebView 生效。
  - **Per-controller UA**：在每个 WebView 的 `onControllerAttached` 中调用 `ctrl.setCustomUserAgent(customUserAgent)`，作为防御性冗余。
- `customUserAgent` 常量定义在 `[entry/src/main/ets/common/constants.ets](entry/src/main/ets/common/constants.ets)` 第 26 行。
- 5 个目标页面目前都**没有**设置 UA，虽然全局 UA 可能在 Dashboard 初始化后生效，但如果这些页面作为独立 Ability 启动（Dashboard 未运行），则 UA 缺失。

## Design

### 修改策略

在每个目标页面的 `onControllerAttached` 回调中，仿照 `Dashboard.ets` 的模式（第 592-598 行）添加 `setCustomUserAgent` 调用：

```ets
.onControllerAttached(() => {
    try {
        if (this.url !== "") {
            this.web_controller.loadUrl(this.url);
        }
        this.web_controller.setCustomUserAgent(customUserAgent);
    } catch (e) {
        console.error(`WebController attach error: ${e}`);
    }
})
```

此方案：
- 最小侵入性：只改动 `onControllerAttached` 回调，不改变页面结构
- 与 Dashboard 一致：复用同一 UA 常量和方法
- 防御性：`try-catch` 包裹，避免 UA 设置失败影响页面加载

### ArkTS 特定考虑

- 无需生命周期变更
- 无需新权限
- 无需新资源文件
- 不涉及状态管理变更

## Risks And Compatibility

- **风险极低**：仅添加一行 `setCustomUserAgent` 调用，使用已有常量，不改变任何业务流程。
- **兼容性**：`setCustomUserAgent` 是 ArkWeb 标准 API，在 HarmonyOS NEXT（API 11+）上完全支持。该项目的 `deviceInfo.sdkApiVersion > 20` 检查已在 Dashboard 全局 UA 中处理，per-controller 调用不受影响。
- **回退**：如果某页面出现 WebView 加载异常，只需移除新增的 `setCustomUserAgent` 调用即可恢复。

## Rollback

1. 对每个修改的文件，删除新增的 `setCustomUserAgent` 行，恢复 `onControllerAttached` 回调为原始形式。
2. 删除新增的 `import { customUserAgent }` 行。
3. 重新编译验证。
