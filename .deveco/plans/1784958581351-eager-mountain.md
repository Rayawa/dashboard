# Fix ability 模块 queryWeb / continueWeb URL 解析和 scrollDistance 还原问题

## Goal
修复 ability 模块下三个核心问题：
1. `query.ets`（ShareExtensionAbility）的 URL 解析只匹配 `?id=` 格式，导致多种 URL 格式无法查询
2. `continueWeb.ets` 的 `scrollDistance` 滚动位置还原完全失效（onPageEnd 重复注册覆盖）
3. `continueWeb.ets` 的 URL 可能被 `queryUrlFromAbility`（来自 query 流程）交叉污染

## Scope / Non-goals
- **包含**：query.ets 解析逻辑、continueWeb.ets 双 onPageEnd 合并、continueWeb.ets URL 取值路径清理、ability pages 的 share 数据同步
- **不包含**：主应用 pages/queryWeb.ets 的改动（该文件无需修改）、Dashboard.ets 的改动（主应用分享和接续逻辑已正确）、UI 样式调整

## Current State And Constraints

### 问题 1：`query.ets` 的 `extractPkg` 正则过于狭窄

**现状**（[ability/query.ets](ability/query.ets) 第 61-64 行）：
```typescript
private extractPkg(url: string): string | null {
    const match = url.match(/[?&]id=([^&]+)/);
    return match ? match[1] : null;
}
```
- 仅匹配 URL query string 中的 `id=xxx` 或 `&id=xxx`
- 无法处理路径中包含包名/AppID 的 URL（如 `https://appgallery.huawei.com/app/C106957691`）
- 而同模块的 `complexSubmit.ets` 和 `simpleSubmit.ets` 已使用 `parseInputSplitLinksPkgsAndAppIds` 支持多种格式

### 问题 2：`continueWeb.ets` 双重 `onPageEnd` 导致 scroll restoration 死代码

**现状**（[abilityPages/continueWeb.ets](abilityPages/continueWeb.ets)）：
- **第 219-222 行**：设置滚动还原 — `.onPageEnd(() => { if (this.scrollDistance > 0) { this.web_controller.runJavaScript(...) } })`
- **第 244 行**：设置 loading 状态 — `.onPageEnd(() => (this.isLoading = false))`
- ArkUI 中同一事件链式调用仅最后一个生效 → 第 219 行的 scroll restoration 被第 244 行覆盖，永远不会执行

### 问题 3：`queryUrlFromAbility` 跨流程污染

**现状**（[abilityPages/continueWeb.ets](abilityPages/continueWeb.ets) 第 143-148 行）：
```typescript
const storageUrl = AppStorage.get<string>('queryUrlFromAbility');
if (storageUrl) {
    this.url = storageUrl;  // 覆盖 @StorageLink('pageUrl') 的正确接续 URL！
    AppStorage.setOrCreate('queryUrlFromAbility', '');
}
```
- `continueWeb.ets` 本身应该通过 `@StorageLink('pageUrl')` 从 `entry.ets` 传入的 `LocalStorage` 获取接续 URL
- 但 `aboutToAppear` 中额外检查了 `AppStorage` 中的 `queryUrlFromAbility`，如果此前用户使用过 query 功能，该值会错误覆盖正确的接续 URL

### 问题 4（连带）：ability pages 未同步 share URL

`abilityPages/queryWeb.ets` 和 `abilityPages/continueWeb.ets` 的 Web 组件均未在 `onPageEnd` 中调用 `this.shareManager?.updateShareData(realUrl)`，导致被动分享（碰一碰/隔空传送）使用过期的缓存 URL。

### ArkTS 约束
- 需注意 `query.ets` 中 `parseInputSplitLinksPkgsAndAppIds` 的导入
- regex 字面量不可用，改为 `new RegExp()`（现有 `extractPkg` 中的正则需调整）
- 使用 `ctrl.getUrl()` 获取 Web 实际 URL

## Design

### 修复 1：`query.ets` 使用 `parseInputSplitLinksPkgsAndAppIds`

将 `extractPkg` 替换为对 `parseInputSplitLinksPkgsAndAppIds(rawContent)` 的调用：
- 若结果中有 `pkgs`（包名），取第一个用于 `getAppIdByPackage`
- 若仅有 `app_ids`（AppID），直接跳过 `getAppIdByPackage`，进入 `verifyAppIdExists`

**变更文件**：[ability/query.ets](ability/query.ets)

**伪代码**：
```typescript
import { parseInputSplitLinksPkgsAndAppIds } from '../common/utils';

// 删除 extractPkg 方法

// onSessionCreate 内：
const res = parseInputSplitLinksPkgsAndAppIds(rawContent);
const pkg = res.pkgs.length > 0 ? res.pkgs[res.pkgs.length - 1] : '';
const appIdFromUrl = res.app_ids.length > 0 ? res.app_ids[res.app_ids.length - 1] : '';

let appId = appIdFromUrl;
if (!appId && pkg) {
    appId = await this.getAppIdByPackage(pkg);
}
if (!appId) throw new Error("无法解析应用标识");
const exists = await this.verifyAppIdExists(appId);
// ... 后续不变
```

### 修复 2：合并 `continueWeb.ets` 的 `onPageEnd`

将两个 `onPageEnd` 合并为一个：
```typescript
.onPageEnd(() => {
    this.isLoading = false;
    if (this.scrollDistance > 0) {
        this.web_controller.runJavaScript(`window.scrollTo(0, ${this.scrollDistance})`);
    }
})
```

**变更文件**：[abilityPages/continueWeb.ets](abilityPages/continueWeb.ets)（删除第 219-222 行，合并到第 244 行）

### 修复 3：移除 `continueWeb.ets` 的 `queryUrlFromAbility` 回退

`continueWeb.ets` 的 URL 来源应为 `@StorageLink('pageUrl')`（由 `entry.ets` 通过 `LocalStorage` 注入），删除 `aboutToAppear` 中的 `queryUrlFromAbility` AppStorage 检查逻辑。

删除代码块（第 143-148 行）：
```typescript
// 删除：
else {
    const storageUrl = AppStorage.get<string>('queryUrlFromAbility');
    if (storageUrl) {
        this.url = storageUrl;
        AppStorage.setOrCreate('queryUrlFromAbility', '');
    }
}
```

同时删除不需要的 `router.getParams()` 回退（第 139-141 行），因为 `continueWeb` 是直接由 `windowStage.loadContent` 加载，不会经过 router。

`aboutToAppear` 简化为：保留 settings 加载和 share 初始化，移除 URL 设置逻辑（URL 已由 `@StorageLink` 自动绑定）。

### 修复 4：ability pages 同步 share URL

在 `abilityPages/queryWeb.ets` 和 `abilityPages/continueWeb.ets` 的 `onPageEnd` 中增加：
```typescript
.onPageEnd(() => {
    this.isLoading = false;
    try {
        const realUrl = this.web_controller.getUrl();
        this.shareManager?.updateShareData(realUrl);
    } catch (e) {
        // controller not ready, ignore
    }
})
```

**变更文件**：
- [abilityPages/queryWeb.ets](abilityPages/queryWeb.ets)
- [abilityPages/continueWeb.ets](abilityPages/continueWeb.ets)（合并到已修复的 onPageEnd 中）

## Verification

| 验证项 | 方法 | 预期结果 |
|---|---|---|
| ArkTS 编译检查 | `arkts_check` 对 query.ets, continueWeb.ets, queryWeb.ets | 无 error |
| query 通用性 | 分享不同格式的应用链接（包名路径、id 参数、AppID 路径） | 均能查到并加载对应页面 |

## Risks And Compatibility

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| `parseInputSplitLinksPkgsAndAppIds` 可能返回空的 pkgs/app_ids | 查询失败，抛出异常 | 保持现有 try-catch 错误处理，异常被记录和透传 |
| 移除 continueWeb 的 AppStorage 回退后，非接续场景无法获取 URL | 理论上 continueWeb 仅用于接续场景 | continueWeb 由 entry.ets 在接续时加载，非接续不会进入此页面 |
| `ctrl.getUrl()` 在 onPageEnd 外可能返回空 | share URL 更新失败 | try-catch 包裹，静默忽略 |
