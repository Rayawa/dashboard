# AppDetailPage 断点适配

## Goal

让 [AppDetailPage.ets](entry/src/main/ets/pages/detail/AppDetailPage.ets) 与首页/我的页面一致地响应 `600vp` / `840vp` 断点：

- 详情字段（`DetailTag`）从固定 `Flex({ wrap })` 换行改为 `GridRow/GridCol` 栅格，按断点自动 1/2/3 列。
- 两张折线图（下载量趋势、评分趋势）在 `≥840vp` 时左右并排，否则保持上下堆叠。
- 页面整体仍为**一个 `Scroll`**（含下拉刷新、滚动位置保存/恢复），**不做** Home/My 那种「左侧固定 + 右侧独立滚动」的双滚动布局。

## Scope / Non-goals

**包含**
- 详情字段多列（600/840 断点）。
- 双折线图大屏并排。
- 内容区宽度测量（`contentWidth`）。

**不包含**
- 顶部应用概要卡、操作按钮、截图 Swiper、应用介绍等其它区块的布局改造。
- 不改变数据加载、缓存、分享、接续、下拉刷新等逻辑。
- 不新增权限或资源文件。

## Current State And Constraints

- 现状：[AppDetailPage.ets](entry/src/main/ets/pages/detail/AppDetailPage.ets) 无任何断点逻辑，结构为 `HdsNavDestination → Stack → Refresh → Scroll(scroller) → Column({ space: 14 })`，内容列使用 `.constraintSize({ maxWidth: CONTENT_MAX_WIDTH })`（1440）。
- 详情字段当前是 `Flex({ wrap: FlexWrap.Wrap, justifyContent: FlexAlign.Start, alignItems: ItemAlign.Start })`（约 21 个 `DetailTag`）。
- 两张 `InteractiveLineChart` 当前依次上下堆叠。
- 断点常量已存在：[constants.ets](entry/src/main/ets/common/constants.ets) 中 `RESPONSIVE_BREAKPOINT_MEDIUM = '600vp'`、`RESPONSIVE_BREAKPOINT_LARGE = '840vp'`、`CONTENT_MAX_WIDTH = 1440`。
- 参考模式：
  - HomePage `statsGrid` 用 `GridRow({ columns, gutter, breakpoints: { value: [600vp, 840vp], reference: BreakpointsReference.WindowSize } })` + `GridCol({ span })`。
  - Home/My 用 `@State contentWidth` + `.onAreaChange` + `if (this.contentWidth >= 840)` 做双栏切换。
  - OverviewSection 用 `GridRow({ columns: contentWidth >= 840 ? 4 : (>=600 ? 3 : 2) })` + `if (contentWidth >= 840) Row{...}` 在**单滚动**内做响应式，最贴近本页需求。

**ArkTS 约束**：不引入 `any/unknown/as`；`GridRow`/`GridCol`/`BreakpointsReference` 为 ArkUI 全局可用，无需额外 import；`RESPONSIVE_BREAKPOINT_*` 需从 constants 显式导入；栅格 `columns`/`span` 对象字面量作为组件参数是允许的（同 HomePage 用法）。

## Design

在保持 `Scroll` 单滚动不变的前提下，加入 `contentWidth` 测量 + 两处内容级响应式改造：

### 1. 内容宽度测量
- 新增 `@State private contentWidth: number = 0;`（与其它 `@State` 放在一起）。
- 在内容 `Column({ space: 14 })`（当前约 line 368）上新增 `.onAreaChange`，把 `Number(newValue.width)` 写入 `contentWidth`。该列因 `.constraintSize({ maxWidth: CONTENT_MAX_WIDTH })` 实际宽度 = `min(视口, 1440)`，测量结果精确反映内容区宽度。
- `contentWidth` 用于图表的 `>= 840` 并排判断（600/840 断点）。

### 2. 详情字段改栅格（多列）
将现有 `Flex({ wrap: ... })`（约 line 512-523）替换为：

```
GridRow({
  columns: { xs: 1, sm: 2, md: 3 },
  gutter: { x: 8, y: 8 },
  breakpoints: {
    value: [RESPONSIVE_BREAKPOINT_MEDIUM, RESPONSIVE_BREAKPOINT_LARGE],
    reference: BreakpointsReference.WindowSize,
  },
}) {
  ForEach(this.fields(), (field: DetailField) => {
    GridCol({ span: 1 }) { DetailTag({ field }) }
  }, (field: DetailField) => field.label)
}
.width('100%')
.padding(12)
.borderRadius(16)
.backgroundColor($r('app.color.v3_surface'))
.border({ width: 1, color: $r('app.color.nd_card_border') })
.accessibilityText('以标签形式展示的应用详细字段')
.transition(contentEnterTransition(10))
```

- `columns: { xs: 1, sm: 2, md: 3 }` + `GridCol({ span: 1 })` ⇒ 小屏 1 列、中屏 2 列、大屏 3 列。
- 外层 `.width/.padding/.borderRadius/.backgroundColor/.border/.accessibilityText/.transition` 从原 Flex 平移到 GridRow 上，保持不变。

### 3. DetailTag 填满单元格
`DetailTag` 的根 `Row({ space: 7 })` 当前是内容自适应宽度且带 `.margin(4)`：
- 给根 `Row` 加 `.width('100%')`，使其占满栅格单元格，三列对齐。
- 去掉 `.margin(4)`，改用 GridRow `gutter` 提供间距，避免双重留白。
- 其它（字号、颜色、按压动效、无障碍文本）不变。

### 4. 折线图响应式并排
将两张 `InteractiveLineChart`（约 line 558-580）改为：

```
if (this.contentWidth >= 840) {
  Row({ space: 14 }) {
    InteractiveLineChart({ 下载量趋势... }).layoutWeight(1)
    InteractiveLineChart({ 评分趋势... }).layoutWeight(1)
  }
  .width('100%')
  .alignItems(VerticalAlign.Top)
} else {
  InteractiveLineChart({ 下载量趋势... })
  InteractiveLineChart({ 评分趋势... })
}
```

- `≥840vp`：两图并排各占一半（`layoutWeight(1)`），顶部对齐；`InteractiveLineChart` 根已 `.width('100%')`，会填满分配到的单元格。
- `<840vp`：保持原上下堆叠。
- 两张图的 `title/unit/points/lineColor/enablePressEffect/viewport/onViewportChange` 参数与现有完全一致，仅做位置包装；各自的 `.transition(contentEnterTransition(10))` 保留。
- `InteractiveLineChart` 内部已有 Canvas `.onAreaChange` 重绘，宽度变化会自动重绘，无需额外处理。

## Risks And Compatibility

- **GridRow WindowSize 断点 vs contentWidth**：详情字段用 `BreakpointsReference.WindowSize`，图表用 `contentWidth`。因内容最大宽度 1440 > 840，二者在「哪个区间」上不会出现分歧；仅当未来 `CONTENT_MAX_WIDTH` 被改到 <840 时才需重审。
- **DetailTag 去掉 margin**：视觉留白改由 `gutter { x:8, y:8 }` 承担，字段标签密度略有变化（可接受，如需更紧凑可调小 gutter）。
- **图表并排宽度**：并排时每图宽度约减半，Canvas 依赖 `onAreaChange` 重绘（已有实现），但需在真机确认缩放/拖动手势在半宽下仍灵敏。
- **SDK 版本**：`GridRow/GridCol`、`BreakpointsReference`、`onAreaChange` 均为项目既有 API，无新增 SDK 依赖。
